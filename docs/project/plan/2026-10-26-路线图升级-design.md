## 4. 数据模型与文件布局

新增 `Study/plan/roadmap.toml` 作为路线图正本：

```toml
# Study/plan/roadmap.toml — Go 学习路线图（树状正本）
version = 1

[[branch]]                          # 主干
title = "并发编程"

  [[branch.topic]]                  # 枝干
  title = "Goroutine 与调度"

    [[branch.topic.node]]           # 叶子知识点
    title = "GMP 调度模型"
    status = "doing"                # todo(默认,可省略) | doing | done
    tags = ["高频"]                  # 可选，树上标 *
    links = [                       # 可选，挂载的知识笔记（工作区相对路径，含 Study/ 前缀）
      "Study/sea/clip/GMP调度详解.md",
      "Study/river/GMP调度.md",
    ]
    note = ""                       # 可选备注
```

约束：

- 三级固定层次：branch → topic → node；不做任意深度（YAGNI）。
- 树只存「标题 + 状态 + 索引信息」，知识点详情归三层笔记管。
- `links` 为工作区相对路径（含 `Study/` 前缀），与出处链、ListTierFiles 同规范；不限制指向类型，文件不存在时视图标 `[失效]`，不自动清理（知识绑定设计定，见 [2026-10-26-知识绑定-design.md](./2026-10-26-知识绑定-design.md)）。
- `status` 缺省视为 `todo`；非法值解析报错。
- 文件写入一律走原子写（临时文件 + rename），延续全局硬性规则 5。
- 平时用命令维护；批量调整可手编 TOML，解析器对格式错误给出带行列号的友好报错。

## 5. 命令面

| 命令 | 行为 |
|---|---|
| `plan` | 默认 = 全景树 pager；树顶两行：总进度统计（`进度 n/m (p%)`）+ 「下一步」断点摘要（读自学习状态.md 当前断点的「下一步」键） |
| `plan <主干关键词>` | 只渲染标题含关键词的主干（如 `plan 并发`）；零匹配报错并列出全部主干名 |
| `plan status` | 原状态速览视图（现默认视图整体迁入，渲染逻辑一字不减） |
| `plan next <描述>` | 保留不变（更新学习状态.md 的「下一步」并刷新更新时间） |
| `plan done/doing/todo <关键词>` | 标记叶子状态：关键词在全树叶子标题中匹配，唯一直接改，多匹配弹 huh select，无参数进入纯交互（主干→枝干→叶子逐层选） |
| `plan add` | 建树期录节点：`plan add node <主干/枝干> <标题>`；branch/topic 同理；缺参交互补全 |
| `plan edit` | 保留；文件列表中加入 roadmap.toml（DOCX 提示语保留） |

子命令消歧规则：`plan` 后第一个参数若为 `status` / `next` / `edit` / `done` / `doing` / `todo` / `add` 之一则按子命令处理，否则视为主干过滤关键词（主干命名避开这些保留字）。

范围外（v1 不做，手编 TOML 兜底）：rename / move / delete 命令；树上「◀ 当前断点」节点标注（树顶摘要行已覆盖需求，后续想要再加）；多路线图（第一版只有一张 Go 后端路线图）。

## 6. 渲染设计

```
Go 学习路线图                      进度 23/96 (24%)
下一步：改用问题驱动方式选择下一条支线
══════════════════════════════════════════
├─ 语言基础 ······················ 8/16
│  ├─ 语法核心
│  │  ├─ [x] slice 扩容机制
│  │  ├─ [~] map 底层结构 *
│  │  └─ [ ] struct 可比较性
│  └─ 方法与接口
│     └─ [ ] iface/eface 底层 *
├─ 并发编程 ······················ 5/20
│  ...
```

- 状态符号：`[x]` 已学 / `[~]` 进行中 / `[ ]` 未学；配合同色系明度区分的颜色（沿用 ui 包现有主题色板；遵守硬性规则：不用 emoji、不用彩亮饱和色）。
- 主干行右侧挂该主干进度 `n/m`；枝干行不挂进度（降噪）。
- `tags` 含「高频」的叶子标题尾随 ` *`。
- 树顶「下一步」行读自学习状态.md；文件缺失时降级显示「（未找到学习状态.md）」，树照常渲染。
- `links`/`note` 不在树视图展示（保持树简洁；挂载信息的展示由知识绑定设计在 `plan <主干>` 过滤视图承担，见 [2026-10-26-知识绑定-design.md](./2026-10-26-知识绑定-design.md)）。

## 7. 代码架构

延续全局硬性规则 4「命令层纯逻辑与交互壳分离」，新增 `internal/roadmap` 纯逻辑包：

```
internal/roadmap/
├── roadmap.go   # Roadmap/Branch/Topic/Node 类型；Load(path)（解析+校验）、Save(path)（原子写）
├── ops.go       # 关键词匹配（返回唯一/多/零三态）、状态变更、Add 节点（同枝干查重）
└── render.go    # 树渲染纯函数，输出文本；颜色经回调注入（Color func(status string) string），
                 # 包本身不 import ui/lipgloss，可独立测试
```

- `internal/command/plan.go` 只做壳：子命令分发、huh select 交互、调 pager（runViewPager）。
- 树顶断点摘要由壳层读状态文件（复用现有 `ParseState` 取「下一步」KV）后传入渲染——`roadmap` 包不感知学习状态.md，保持纯。
- 现有 `plan next`、`plan status`（原默认渲染 renderPlan/ParseState）逻辑不动，仅默认视图换成树。
- `workspace` 包新增 `RoadmapFile()` 路径方法（对齐 StateFile/PlanDir 现有模式）。

## 9. 错误处理

- TOML 解析失败：报错含行列号，提示 `plan edit roadmap` 修复；REPL 不崩。
- `add` 查重：同枝干下重名叶子报错；跨枝干允许重名。
- 关键词零匹配（状态标记）：报错并列出同层候选标题；多匹配弹 select。
- 学习状态.md 缺失：树视图照常，断点摘要行降级显示「（未找到学习状态.md）」。
- roadmap.toml 不存在：`plan` 提示「路线图尚未生成（初稿由本次实施任务产出）」并给出 `plan status` 替代入口；不自动创建空文件。

## 附录 A · Go 学习路线三层大纲（调研综合版）

> 来源：eddycjy/go-developer-roadmap、yongxinz/gopher、Quorafind/golang-developer-roadmap-cn-2021、roadmap.sh/golang；按 Go 后端实习面试导向综合。【高频】= 面试高频，落 toml 时打 `tags = ["高频"]`。

- **A. Go 语言基础**
  - A1. 语法核心：变量/常量、基础与复合类型（slice/map/struct/array）【高频：slice 扩容、map 底层与负载因子】、流程控制、函数
  - A2. 方法与接口【高频】：interface 底层（iface/eface）、类型断言、值接收者 vs 指针接收者、结构体可比较性
  - A3. 错误处理【高频】：error 嵌套与包装、defer/panic/recover、defer 闭包坑
  - A4. 传值语义与面向对象【高频】：传值 vs 传引用、new vs make、组合优于继承
  - A5. 包管理：Go Modules（版本、工作区、依赖治理）
- **B. 并发编程**
  - B1. 基础原语【高频】：goroutine 与线程区别、channel（有/无缓冲、关闭语义）、select、WaitGroup
  - B2. 同步原语【高频】：Mutex/RWMutex、sync.Map vs 原生 map、sync.Once、atomic
  - B3. context【高频】：取消传播、超时控制、context 用途
  - B4. 并发模式与陷阱【高频】：数据竞争与 `-race`、死锁、goroutine 泄漏、worker pool
- **C. 运行时原理**
  - C1. GMP 调度【高频】：为什么需要 P、调度策略与抢占、g0/m0、单核死循环行为
  - C2. 内存与 GC【高频】：三色标记、混合写屏障、逃逸分析、内存分配（mcache/mcentral/mheap）
  - C3. 语言设计哲学：字符串不可变、for-range 语义、struct tags、泛型
- **D. Web 工程化**
  - D1. HTTP 框架：Gin【高频：路由/中间件/参数绑定与校验】、Echo/Chi（对比即可）
  - D2. 工程分层【高频】：Handler/Service/Repository、统一响应、错误码、日志（Zap/slog）、配置（viper）
  - D3. 鉴权【高频】：JWT、Session/Cookie、认证基础
  - D4. RPC 与 API：gRPC、Protobuf、grpc-gateway、REST 设计
- **E. 存储与中间件**
  - E1. MySQL【高频】：索引与 EXPLAIN、事务与隔离级别、慢查询、表设计
  - E2. Redis【高频】：数据类型、缓存穿透/击穿/雪崩、缓存一致性、分布式锁
  - E3. ORM：GORM（原理与坑）
  - E4. 消息队列：Kafka/RabbitMQ 基础、异步任务
- **F. 网络与系统**（枝干级占位）
  - F1. 网络协议【高频】：TCP 三次握手/四次挥手、HTTP/HTTPS、连接复用
  - F2. Linux 基础：进程/端口/日志/常用命令
- **G. 分布式与微服务**（枝干级占位）
  - G1. 微服务框架：go-zero/kratos（选型认知）
  - G2. 服务治理：限流（令牌桶/计数器）【高频】、熔断、服务发现
- **H. 工程实践**（枝干级占位）
  - H1. 测试：单元测试、testify、GoMock、表驱动测试
  - H2. 调试与剖析：Delve、pprof、trace、PGO
  - H3. 设计模式与代码规范：Uber Go 规范、常用 Go 模式
  - H4. 版本特性：1.18+ 泛型、1.21 slog、1.22/1.23 迭代器（面试谈资）
- **I. 算法与面试**（只挂主干，不展开；算法保留为独立练习）
  - I1. 高频题型、I2. 项目表达（架构讲述、性能对比、个人贡献）
