## 1. 背景与动机（开发者原话整理）

- 查看 plan 时发现系统自动归类的知识点下有放错位置的文件：「基础类型与零值」下挂着 `Study/sea/Go语言基础/1.1.2 Go语言基础操作.md`，希望移到其他合适的地方，但目前没有这种操作。
- plan 的知识点规划分类当时粗看觉得可以，细看需要微调：想把一些知识点合并、拆成其他角度等，想要自己手动操作，目前实现不了。
- 补充要求：**所有文件都必须和 plan 有绑定**——找不到对应知识点的也要在 plan 的「待归类区」集中可见，不能散架。

## 2. 现状盘点与缺口

- roadmap v2 以 roadmap.toml 为绑定正本：sea/ship/river 数组 0..N，spring/code 单值 0/1；知识点标题全树唯一。
- 现有 40 个知识点的 sea 绑定是 v2 初稿内容商讨时一次性写入的，此后**无任何调整入口**（浏览器重构设计 v1 明确「sea 挂载不做专用命令，浏览器只读展示」「rename/move 手编 TOML 兜底」）。
- `internal/roadmap` 已有 Bind 系列与 MoveTierBinding/CopyTierBinding（服务于 ship/river 流转的绑定跟随），缺卸载/移动/挂载/合并/拆分/改名/换主干/换分组/删除。
- planview 浏览器现有三层视图（全局树/主干页/详情页）+ d/s/t 标记 + Enter/o 打开笔记，Hooks 仅 OpenNote/Save 两回调；详情页五清单节：spring、code、river、ship、sea。

## 3. 已确认的关键决策（brainstorming 问答记录）

| # | 问题 | 决策 |
|---|---|---|
| 1 | 操作入口 | **浏览器内按键**（命令层子命令、混合方案均否） |
| 2 | 结构操作范围 | 合并、拆分、改名、换主干、换分组、删除**全要** |
| 3 | 绑定操作覆盖 | **全部绑定类型**（sea/ship/river/spring/code）统一键位 |

| 5 | 键位 | `n` 改名直键；合并/拆分/换主干/换分组/删除收进 `o` 菜单；`x` 卸载、`m` 移动、`a` 挂载 |

## 4. 交互设计

### 4.1 详情页绑定操作（光标在笔记行）

| 键 | 操作 | 说明 |
|---|---|---|
| `x` | 卸载 | 从当前知识点清单摘除该条绑定；只动 roadmap.toml，文件留磁盘原地（变无主，进待归类区） |
| `m` | 移动 | 卸载 + 选目标知识点（关键词过滤，可跨主干）一步完成 |
| `a` | 挂载 | 反向：从对应根目录挑**未被任何知识点绑定**的文件挂到光标所在清单节 |

- `a` 作用域 = 光标当前所在清单节；扫描根：sea→`Study/sea`、ship→`Study/ship`、river→`Study/river`、spring→`Study/spring`、code→`Study/code`（code 含 .go，其余 .md）。
- spring/code 单值语义：`x` = 清空字段；`m` 目标已有值 → 提示冲突、操作取消（不允许覆盖）；`a` 本点已有值 → 提示先卸载。
- 操作后清单即时刷新、即时原子落盘（沿 d/s/t 模式）。

### 4.2 知识点行结构操作（全局树/主干页的光标在知识点行）

| 键 | 操作 | 规则 |
|---|---|---|
| `n` | 改名 | 输入新标题，全树查重；spring 字段若等于约定路径 `Study/spring/<旧标题>.md` → 同步改字段，且该文件存在时文件一并改名；非约定路径 → 字段不动并提示 |
| `o` | 结构菜单 | 弹菜单选：合并 / 拆分 / 换主干 / 换分组 / 删除 |

`o` 菜单各项规则：

- **合并**：光标点 A，再选点 B → **B 并入 A**（A 保留，B 从树删除）。sea/ship/river 合并去重；spring/code 两边都有 → 弹选择保留哪边，落选文件留磁盘变无主；status 取进度高者（done > doing > todo）；group/title 沿用 A；tags 取并集；note 拼接（B 非空时追加）。执行前列摘要确认。
- **拆分**：输入新知识点标题（全树查重）→ 新点插 A 正后方、同分组、status=todo → 对 sea/ship/river 逐清单多选分配给新点（默认全不选 = 全留 A）；spring/code 留 A（事后可 `m`）。
- **换主干**：选目标主干 → 知识点连带全部绑定挪至该主干末尾。
- **换分组**：输入新分组标签，可清空。
- **删除**：仅五个绑定（spring/code/river/ship/sea）全空时允许；非空拒绝并列出未清绑定；确认后删除。

### 4.3 待归类区（无主文件集中地）

- 全局树尾部新增伪主干行「待归类区」，Enter 进入独立视图（第四视图）。
- 内容 = 五类 tier 文件中**未被任何知识点绑定**者，按类型分组列出：`sea · 未归类 ×N`、`ship · 未归类 ×N`、`river · 未归类 ×N`、`spring · 未归类 ×N`、`code · 未归类 ×N`。
- 扫描根与扩展名同 §4.1；目录不存在按 0 计。
- 行按键：Enter/o 打开阅读；`a` 挂载到选定知识点（关键词过滤）。挂载时若该文件已被其他知识点挂载（进入视图后被他处挂上）→ 提示「已挂载于 X」并询问转为移动。
- 待归类区是反查计算视图：文件永远留在原目录，进度统计不受影响。

### 4.4 键位总表

| 视图 | 行 | 键 | 行为 |
|---|---|---|---|
| 详情页 | 笔记行 | `x` | 卸载绑定 |
| 详情页 | 笔记行 | `m` | 移动到其他知识点 |
| 详情页 | 任意行（定节） | `a` | 挂载未归类文件到本节 |
| 全局树/主干页 | 知识点行 | `n` | 改名 |
| 全局树/主干页 | 知识点行 | `o` | 结构操作菜单 |
| 全局树 | 待归类区行 | Enter | 进入待归类区 |
| 待归类区 | 文件行 | `a` | 挂载到知识点 |
| 待归类区 | 文件行 | Enter/o | 打开阅读 |

既有键位不变：↑↓/j/k 移动、Tab 展开、Esc 逐层返回、q 退出、d/s/t 状态标记。

## 5. 代码架构

延续硬性规则「命令层纯逻辑与交互壳分离」：

```
internal/roadmap/ops.go      # 扩展纯逻辑（不 import ui、不碰文件系统）：
                             # UnbindSpring/UnbindCode（清空）、UnbindList（数组卸载，幂等）、
                             # MoveBinding(src, tier, rel, dst)（卸载+挂载）、
                             # RenamePoint(ref, newTitle)（查重；spring 字段约定跟随）、
                             # MergePoints(keep, absorb)（绑定合并去重、absorb 删除；
                             #   spring/code 冲突由壳层先裁决）、
                             # SplitPoint(ref, newTitle)（同组新点，todo）、
                             # MovePointToBranch(ref, bi)、SetGroup(ref, group)、
                             # DeletePoint(ref)（空点校验）、IsBound(rel)（待归类区判定）

internal/planview/           # 交互壳扩展：
├── state.go                 # 第四视图 viewUnbound 行计算；row 动作语义扩展
│                            # （ActUnbind/ActMove/ActAttach/ActRename/ActMenu…）
├── browser.go               # 新键位分发；交互子流程经 Hooks 回调——退 raw →
│                            # 行式选择/文本输入/确认 → 重进 raw（复用 pauseAndOpen 模式）；
│                            # 操作成功即 h.Save，失败写 m.Err
└── view.go                  # 待归类区渲染（配色沿用 ui 主题，无 emoji）

Hooks 扩展（command 层装配注入）：
  SelectPoint(kw…) → 选知识点；Input(提示) → 文本输入；Confirm(摘要) → 确认；
  UnboundFiles(tier) → 未挂载文件扫描（惰性，进视图时重扫）
```

- 文件系统 IO（spring 文件跟随改名、未挂载扫描）在 command 装配层实现；roadmap 包纯逻辑，planview 状态机沿 Exists 注入惯例不直接依赖真实文件。
- `/plan` 非 TTY 静态降级输出不变，维护操作仅交互模式可用；seaport 自动导入、`/ship` `/river` 流转命令不受影响。

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| 落盘失败 | 底部错误行提示，不退出（沿 d/s/t 模式） |
| 改名/拆分标题全树重名 | 报错不落盘，停留原处 |
| 移动 spring/code 到已有值的知识点 | 提示冲突，操作取消 |
| 挂载时本点 spring/code 已有值 | 提示先卸载 |
| 删除非空知识点 | 拒绝并列出未清绑定 |
| 合并双方都有 spring/code | 弹选择保留方，落选文件留磁盘进待归类区 |
| 挂载目标已被其他知识点挂载 | 提示「已挂载于 X」，询问转为移动 |
| 待归类区扫描目录不存在 | 该类型计 0，不报错 |
| 交互子流程（选择/输入）中放弃 | 取消整个操作，不产生半截变更 |

## 7. 测试与验收

- `internal/roadmap` 单测：卸载幂等、MoveBinding（含跨主干）、RenamePoint 查重与 spring 字段跟随（约定/非约定/失效三态）、MergePoints 去重与 absorb 删除与 tags/note 合并、SplitPoint、MovePointToBranch、SetGroup、DeletePoint 空点校验、IsBound、TOML 序列化回读。
- `internal/planview` 状态机表驱动：viewUnbound 行计算（含目录缺失）、row 动作语义映射、操作后行刷新；渲染快照（stripANSI）。
- command 层：未挂载扫描（临时目录，.md/.go、减已绑定）、spring 文件跟随改名（成功/约定不符不动）、Hooks 装配降级。
- 验收：`go build ./...` + `go test ./...` 全绿；真机冒烟——`1.1.2 Go语言基础操作.md` 移动到正确知识点、卸载后待归类区出现并挂载回、合并/拆分各走一遍、改名后 spring 文件跟随、删除空点、全部操作后 roadmap.toml 合法且 `/plan` 重开正常。

## 8. v1 边界（不做）

- 不删任何笔记文件（「删除」仅指知识点节点与绑定记录）；
- 知识点树内排序/拖动（换主干入末尾即可，排序手编 TOML 兜底）；
- 待归类区文件的文件管理（删除/改名文件走既有命令或文件管理器）;
- 非 TTY 静态模式下的维护操作；
- 待归类区的 AI 重新归类建议（先人工挂载，AI 建议后续再议）。
