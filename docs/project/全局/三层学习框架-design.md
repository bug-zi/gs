# 三层学习框架（大海 · 河流 · 泉水）

## 1. 背景与愿景（开发者原话整理）

学习的几个阶段：从外界获取新知识 → 不断理论理解 + 项目代码实践训练巩固 → 沉淀转化为自己的知识 → 用自己的话输出。

据此把 gs 的学习内容划分为三层：

| 层 | 比喻 | 内容性质 | 来源 | 特点 |
|---|---|---|---|---|
| 第一层 | 大海 | 外部知识 | 博主精选文章笔记、向 AI 提问得到的解析问答，全部**复制粘贴**而来 | 信息最多最广最复杂；不是自己写的，不完全属于自己 |
| 第二层 | 河流 | 摘录沉淀 | 从大海中筛选出的、有价值需要反复学习的内容 | 仍不是原创手写，只是学习的沉淀，不完全属于自己 |
| 第三层 | 泉水 | 原创输出 | 自己根据学习经验**亲手写出**的内容 | 记录已学了什么、掌握了哪些知识、自己对知识点的理解 |

- 三层框架针对**学习主模块**；日志、计划作为**支线独立模块**存在（维持现状，不纳入分层）。
- 如何在 gs 中实现——尚未想好，即本文档要商讨的内容。

## 2. 现状对照（gs v1.0.0）

| 现有设施 | 与三层框架的关系 |
|---|---|
| `Study/notes/GPT/*.md` | 现有笔记多数是从 AI 对话粘贴而来 → 性质上偏「大海/河流」，目前**不区分层次** |
| `/AI` 子模式 | 问答产出的解析目前**无处落地**，用完即散 → 大海层最大的录入缺口 |
| `/search` | 全局检索引擎，可作跨层查找底座 |
| `/show` + topics.toml | 主题聚合与沉淀索引机制，思路可借鉴 |
| `/review` | 可天然承担「该沉淀了 / 该输出了」的体检建议 |
| `Study/logs`、`Study/plan` | 支线模块，维持现状不动 |

关键发现：**v1.0.0 里大海层根本没有存储位置**。三层框架的第一个实际价值，就是给外部知识一个家，并建立「外→内」的知识流动通道。

#### 方案甲 v2（细化版）：三层管知识，项目管实践

```
D:\Code\Go\
├── Study\
│   ├── sea\                  # 大海：外来粘贴内容（一主题一文件）
│   │   ├── ai\               #   /AI 会话存档（Q3 已定）
│   │   ├── clip\             #   文章剪藏（导入整理后的归位处，中转方式实现期定）
│   │   └── interview\        #   面试题正本（Q1b 已定）
│   ├── river\                # 河流：摘录沉淀（条目带大海出处链接）
│   ├── spring\               # 泉水：原创输出（主题理解、阶段性总结）
│   ├── logs\                 # 支线：日志（不动）
│   ├── plan\                 # 支线：计划（不动）
│   └── Project\<name>\       # 学习项目：内部结构维持现状
│                             #   （README、docs\log、docs\study 走读、docs\project、interview）
├── Project\<name>\           # 实践项目（不动，其 docs 同理维持现状）
└── Resource\                 # 大资源（不动）
```

四条设计原则：

1. **三层管「知识内容」，项目管「实践载体」**。中心 sea/river/spring 是按主题组织的知识库；项目是实践现场，项目内部的 docs\study 走读笔记、docs\log、设计文档、interview md **保持现状、不入层**——它们服务于具体项目，强行搬中心会割裂项目完整性。
2. **项目与三层的耦合靠「出处链 + 全局检索」缝合**。river/spring 条目可引用项目代码路径作 source；`/search`、`/show` 本来就跨 Study+Project 扫描，把两边缝起来。学习借助项目完成的部分，产出可以两条腿走：项目视角的留在项目 docs，主题视角的写进中心 spring 并链回项目。
3. **/show 是视图不是存储**。show 聚合的素材来自三层 + 项目 docs + 代码 + 日志，本身不新增存放位置；topics.toml 沉淀索引照旧（.gs/topics.toml，路径按新结构更新）。五节视图微调：「② 笔记」节改为「知识」节（river/spring 优先、sea 补充）。
4. **现有 notes/GPT 迁移**：粘贴原样的归 sea，已经自己筛选整理过的归 river；逐个判断或先全入 sea 后再流转向 river，待定（Q1c）。

### Q2 与现有 `Study/notes` 的关系（已解决）

**已确认（2026-10-25，随 Q1c 一并解决）**：`Study/notes/` 目录取消，内容按 Q1c 规则逐个判断拆入 sea / river；`/notes` 命令由新三层命令体系接替（形态见 Q5）。

### Q3 大海的录入方式（已定案）

**已确认（2026-10-25）**：选定两种并存——

1. **/AI 会话一键存档**：`/AI` 子模式问答结束后一条命令把本轮 Q&A 整理成 md 存入 `sea/ai/`，消除「问答用完即散」最大痛点。
2. **文件导入目录**：外部 md / 网页剪藏放入约定目录（实现期定 `sea/` 直接检测或 `sea/inbox/` 中转），gs 检测到后引导整理（起标题、补来源元信息）归位。

不选 REPL 内多行粘贴（终端粘贴长文体验差，两条已选通道已覆盖场景）。

### Q4 层间流动的命令化（已定案）

**已确认（2026-10-25）：命令式流动**（出处链接默认自动带）：

- `/river add`：选择器挑 sea 条目 → 确认摘录范围（全文/选段）→ 落 river，自动带出处
- `/spring add`：选择器挑 river 条目 → 调编辑器手写改写 → 落 spring，自动带出处

浏览视图内按键流动（类似 /show 的 r/w 键）与 AI 缝合式流动不选，可作日后增强。泉水纪律：**只提供编辑器手写入口，不提供粘贴/导入通道**（设计上引导手写，终端内无法强制）。

### Q5 命令命名与交互形态（已定案）

**已确认（2026-10-25）：三命令并列**——`/sea` `/river` `/spring` 三个顶层命令，各自维护查看/新增/编辑子命令，与 `/logs` `/notes` 现有风格一致。不采用 `/learn` 子模式，不扩展 `/notes`（notes 目录取消后该命令由三层体系接替退役）。

### Q6 复习机制（已定案）

**已确认（2026-10-25）：v1 不做**。三层先作为纯组织结构，复习靠自然回访与 `/search`；先把「录入→流动→输出」主链路跑顺。轻量随机重读、间隔复习（SM-2 等）留到真实需求出现后再立项。

### Q7 AI 在三层中的角色（已定案）

**已确认（2026-10-25）：两项都要**——

1. **/review 三层视角**：体检输出增加三类三层建议——大海堆积提醒（久未摘录的条目）、河流待改写清单、泉水产出统计。
2. **/AI 结束询问存档**：`/AI` 子模式问答结束后主动询问「是否存入大海？」，确认后整理落盘至 `sea/ai/`（与 Q3 的一键存档命令并存：询问是默认引导，命令是手动兜底）。

### 补充：/show 模块在新框架下的安排（开发者追问后明确）

**定位**：/show 是跨层聚合的验收演示**视图**，不是存储层——不产生新的内容存放地，素材全部实时引用现有位置；topics.toml 沉淀索引只存「引用 + 演示提示」。三层回答「知识存在哪、怎么流」，/show 回答「知识怎么讲给人听」。

**五节视图调整**：

| 节 | v1.0.0 | 新框架 |
|---|---|---|
| ① 概览 | 出现模块与时间线 | 不变 |
| ② 笔记 | 扫描 Study/notes | 改为「**知识**」节：river/spring 优先展示，sea 补充（大海杂多，不作演示主体） |
| ③ 代码 | 文件 + 行号 | 不变 |
| ④ 日志 | 按时间线 | 不变 |
| ⑤ 面试题 | 扫描各项目内 interview md | 素材源改为 `sea/interview/` 正本为主；项目内如有残留一并纳入 |

**配套调整**：

- topics.toml 机制不变：files 可引用三层文件（工作区相对路径），hint 演示提示保留。
- 旧索引中指向 Study/notes 的路径随迁移失效——依赖现有「失效条目标灰 + 提示清理」机制，不写专门迁移逻辑。
- 热门关键词提取源由「日志 + 笔记标题」改为「日志 + 三层标题」。

## 4. 分期设想（随 Q1–Q7 定案更新）

- **阶段 1 · 存储与迁移**：建 `Study/sea|river|spring/` 目录体系；迁移工具/引导（notes/GPT 逐个判断入 sea/river，各项目 interview md 迁入 `sea/interview/`）；`/search`、`/show` 适配新路径（五节视图「笔记」节改「知识」节）；`/notes` 命令退役。
- **阶段 2 · 录入与流动**：`/AI` 会话一键存档（`/save` 落 `sea/ai/`）；文件导入目录检测与整理引导；`/river add` 摘录、`/spring add` 改写（出处链自动带）。
- **阶段 3 · AI 增强**：`/review` 三层视角；`/AI` 结束默认询问存档。

每阶段独立可用：阶段 1 完成后三层即可手动放文件使用；阶段 2 后主链路（采集→摘录→改写→输出）闭环；阶段 3 锦上添花。
