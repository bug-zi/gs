# 删除机制（软删除 · 五站条目 · roadmap 分支/知识点）

日期：2026-10-28
状态：**brainstorming 定稿，待开发者审阅**——AI 依开发者四项决策整理，覆盖五站条目与 roadmap 分支/知识点的删除能力。

## 1. 背景与目标

gs 现有操作面只有「加」与「改」：五站条目（sea/ship/river/spring/code）可录入编辑，roadmap 可加分支/知识点，但没有任何删除入口。误建条目、废弃知识点、挂错的绑定都无法在 gs 内清理，只能手改文件。

本轮补全删除机制。已核实现状：

- roadmap 纯逻辑层已有 `DeletePoint`（非空拒绝）与 `PointEmpty`；/plan 浏览器 x 菜单已挂「删除」动作（`planview/flows.go doDelete`），但仅空知识点可删，有绑定即拒绝。
- 分支删除、五站条目删除完全缺失。
- 删除的牵连面：roadmap 五类绑定、`topics.toml` 路径引用、其他条目中的出处链（`> 出处：Study/...`）、river 树序编号与 `99-未挂载/` 收容区。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 删除范围 | 五站条目（sea/ship/river/spring/code）+ roadmap 分支/知识点；绑定关系不单设解绑命令（随删除清理） |
| 安全策略 | 回收站软删除：预览影响 → 确认 → 移入回收站，可手动找回；不做硬删除 |
| 入口形态 | 子命令 + 浏览内按键双入口，共用同一套删除逻辑 |
| 删点语义 | 仅解绑、文件保留：删知识点清除其全部绑定，条目文件不删（river 收容 99-未挂载） |
| 实现路径 | 方案 A：纯逻辑落入现有包（tier/roadmap/index），命令壳统一删除流程；不建新包、不做 DeletePlan 抽象 |

## 3. 总体语义

### 3.1 软删除与回收站

- 一切删除 = 移入回收站 `<root>/.gs/trash/<YYYYMMDD-HHMMSS>-<序号>/<原相对路径>`，保留原相对目录结构，手动 mv 回原位即找回。
- 同一秒多次删除用递增序号防碰撞；回收站首次使用时写入 `README.md` 说明找回方法。
- 回收站不做自动过期清理，不提供恢复命令（YAGNI）。

### 3.2 扫描排除（修正项）

`/search` 的 `SearchFiltered` 自工作区根全量扫描，`.gs/` 下的回收站 md 会被索引。默认 `scan.exclude` 增加 `.gs`（config 默认排除表），同时避免未来 .gs 下其他内容入库。

### 3.3 统一流程与引用处理

预览 → `y/N` 确认 → 执行。预览列出三类影响：

1. **文件迁移**：原路径 → 回收站路径。
2. **绑定清理**：roadmap 中指向该文件的绑定将被清除并落盘，逐条列出挂载点。
3. **引用统计**：`topics.toml` 中指向该文件的条目——自动清除，报数量；其他文件出处链指向它的（`tier.CountChainRefs` 计数）——**只警告不动内容**，与「不擅自改内容」纪律一致。

## 4. 五站条目删除

### 4.1 子命令

`/sea del`、`/ship del`、`/river del`、`/spring del`、`/code del`。五站统一覆盖：ship/code 与其余三层共用同一套条目骨架（`newTierCmd`），单独排除反而不一致。流程：

选择条目（复用 `pickTierEntryGrouped`，支持关键词直达）→ 预览 → 确认 → 执行。

### 4.2 各层绑定清理差异

| 层 | 绑定字段 | 清理方式 |
|---|---|---|
| sea | `point.Sea[]` | `UnbindList` 移除 |
| ship | `point.Ship[]` | `UnbindList` 移除 |
| river | `point.River[]` | `UnbindList` 移除 |
| spring | `point.Spring` 单值 | `UnbindSpring` |
| code | `point.Code` 单值 | `UnbindCode` |

spring/code 条目为知识点唯一绑定，删除后该知识点变「未产出」；sea/ship/river 为多绑，删除后仅从命中点的列表移除。

### 4.3 查阅翻页器 `[x]` 键

条目查阅态（`runTierItemView`）提示行变为 `[e]编辑 [x]删除 [r]刷新 [q/Esc]退出`，x 对当前条目走同一套删除流程，删除成功后退出翻页器。翻页器是通用组件（logs/show 复用），删除钩子作为可选回调仅条目查阅传入；钩子为 nil 时提示行不显示 `[x]`，其他视图行为不变。

### 4.4 执行顺序与失败话术

统一顺序（条目删除与删点一致）：**内存变更（清绑定/删点）→ roadmap 落盘 → 文件迁移（回收站）→ 链与 topics 改写**。绑定先清、文件后迁，任一步失败的残留态都是可恢复的：

- 迁移失败：文件原地保留、绑定已清，条目归「未挂载」，重跑 del 跳过已清绑定只补迁移，幂等修复。
- 链/topics 改写失败：不阻断主流程，报错话术同 renumber（失败只报错继续）。

## 5. roadmap 知识点删除（语义升级）

- **现状**：浏览器 `o` 键结构菜单（合并/拆分/换主干/换分组/删除）已挂「删除」动作（`planview/flows.go doMenu` → `doDelete`），但仅空知识点可删，有绑定直接拒绝——与本轮定案的「仅解绑，文件保留」语义不符，本次升级 `doDelete`。（注：`x` 键已被「卸载绑定」占用，删除入口走 `o` 菜单。）
- **新流程**：光标在知识点上 `o` → 菜单「删除」→ 预览影响（复用 `bindingsBrief` 列出 spring/code/river×N/ship×N/sea×N；river 文件逐条列出将收容）→ 确认后执行（顺序同 §4.4：落盘先行、文件迁移在后）：
  1. 清除五类绑定（spring/code 单值、sea/ship/river 列表）后 `DeletePoint`，roadmap 落盘（纯逻辑层「非空拒绝」守卫保留，壳层在内存中先清绑定再调用，清完即空可通过）。
  2. 该点的 river 文件迁移至 `Study/river/99-未挂载/` 收容（目标重名时篇序顺延，同 `riverLanding` 规则）；构造仅含这些文件的迁移集，复用 `tier.ApplyRenumber`。
  3. 同步改写出处链与 `topics.toml`（`RewriteSourceChains` + topics 改写，失败不阻断）。
  4. spring/code/sea/ship 文件原地保留，仅解除绑定（spring/code 变未产出，sea/ship/river 归「未挂载」）。
  - 迁移失败的残留态：river 文件仍在原编号位置但绑定已清，可见于「未挂载」，`/plan renumber` 可收容修复。
- **新增子命令 `/plan del point <关键词>`**：非交互直达路径，`MatchPoints` 定位（多匹配弹选择器）后走同一预览确认流程，与「子命令 + 浏览内按键」入口原则对齐。

## 6. roadmap 分支删除

- **仅空分支可删**：分支下仍有知识点时拒绝，提示先逐个删除/移走知识点。不做级联删除，避免一次确认删掉一片。
- 执行内容：删除 roadmap 分支条目落盘；对应 `Study/river/<NN>-<主干>/` 文件夹若已成空目录，一并移入回收站；完成后提示可运行 `/plan renumber` 重排其余板块编号（renumber 幂等，保持显式触发、不自动跑）。
- 入口两处：浏览器全局树分支行上按 `o` → 菜单「删除分支」（现 `o` 菜单仅知识点可用，扩展分支光标）；子命令 `/plan del branch <关键词>`（复用 `MatchBranches`）。

## 8. 错误处理

- 预览阶段发现目标文件已被外部移动/删除：报错终止，不执行部分删除。
- 条目删除 / 删点收容：roadmap 已落盘、文件迁移失败——残留态为「绑定已清、文件原地保留」，重跑 del 或 `/plan renumber` 幂等修复（§4.4）。
- 链/topics 改写失败：不阻断主流程，报错话术同 renumber。
- 回收站迁移复用 `tier.MoveFile` 的同卷 rename 与错误语义。

- **壳层集成**（`t.TempDir()` 迷你工作区）：`/river del` 等全流程——预览文本内容、取消不落盘、确认后回收站结构、绑定与 topics 落盘、出处链警告计数。
- **planview 状态机**：`doDelete` 升级语义（非空点：预览 → 解绑 → 收容 → 删点）、空知识点快捷路径、分支删除校验与空目录收容。

## 10. 文档同步

- `README.md` 命令一览补 `/sea|ship|river|spring|code del` 与 `/plan del`，数据文件表补 `.gs/trash/`。
- `/help` 输出同步。
- 各层 `design.md` 的命令行为表是否补 `del` 行，由开发者审核本设计后定（AI 不擅改需求正本）。

## 11. 非目标

- 日志删除：`/log` 维持 append-only 纪律，不设删除。
- `topics.toml` 主题整条删除、`projects.toml` 项目注销：本轮范围外，需求出现再立项。
- AI Agent 删除工具：AI 写边界维持只有写（diff 确认），不给删除能力。
- 回收站自动过期清理、恢复命令、级联删除分支。
