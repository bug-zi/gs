# 层条目选择器取消「唯一命中直达」

日期：2026-10-28
状态：**已落地（2026-10-28；tier/roadmap 测试全绿，`go build ./...` 受既有 planview/flows.go WIP 阻塞与本轮无关；真机冒烟待开发者）**
- 已归档：261028 随本轮落地
所属：`全局/`（五层命令共用选择器）

- 需求来源：开发者口述——river 仅一篇笔记时，`/river` 回车后直接进入打开方式询问，缺少笔记标题展示与选择环节；希望仅一条时也保留展示过程。
- 已确认决策：五个层命令（sea/ship/river/spring/code）统一改，不做 river 特例。候选面板的「唯一命中 1s 延迟参数提示」是另一机制，不受影响。

## 改动

- `internal/command/tier_view.go` `pickTierEntryGrouped`：删除 `total == 1` 早退分支，筛选后仅剩一条时照常进入条目选择列表（回车确认、Esc 取消）；板块级选择的跳过逻辑不变（仅一组时本就不弹板块）。
- 同步函数注释：去「唯一命中直达」表述。

## 改动后行为（五层统一）

| 场景 | 行为 |
|---|---|
| 多板块且无关键词 | 板块 → 条目 两级选择（不变） |
| 单板块多条目 | 直接条目选择（不变） |
| 仅一条（含关键词筛剩一条） | 展示单条选择列表，回车确认进查阅，Esc 取消（改） |

## 测试与文档

- 纯函数 `buildRoadmapGroups` / `filterTierGroups` 不受影响，现有测试不动；`pickTierEntryGrouped` 为交互壳层无单测，落地判定 `go build ./...` + `go test ./...` 全绿，真机 `/river` 冒烟由开发者验收。
- 文档冲突：river/design.md、sea/design.md 中「唯一命中直达」表述待开发者审定后同步（开发者主导文件，AI 不擅改）。
