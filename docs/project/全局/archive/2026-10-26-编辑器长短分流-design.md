# gs 编辑器长短分流（CLI 内编辑短文件）— 设计文档

日期：2026-10-26
状态：**已落地**（2026-10-26 实施，build/test 全绿；TUI 交互冒烟待开发者）
所属：跨模块全局改动（edit 包行为调整，影响全部 9 处编辑入口），spec 按机制存放于 `全局/`
背景：编辑器路径含空格 bug 修复（同日）后，开发者提出体验升级：短文件直接在 CLI 内编辑，长文件才调外部软件；外部软件优先 TRAE（开发者已弃用 VS Code，.md 默认应用即 TRAE CN）

---

## 1. 背景与目标

现状：所有编辑入口（logs / plan / show / project / sea / river / spring 共 9 处 `editOpen`）一律调起外部编辑器。目标：

- **短文件**（≤ 20 行）：CLI 内全屏编辑，不离开终端
- **长文件**（> 20 行）：外部编辑器，解析链 **trae 优先**

## 2. 核心决策

| 决策点 | 结论 |
|---|---|
| 分流位置 | 做在 `edit.Open` 内部，所有调用点零改动统一生效 |
| 长短判定 | **只看行数**：≤ 20 行走 CLI，> 20 行走外部；常量 `maxCliLines = 20`，不进配置 |
| CLI 编辑形态 | bubbles/textarea 全屏编辑（`tea.WithAltScreen`），与 B 路线（自绘输入行）同技术栈 |
| 外部编辑器 | `Resolve` 兜底链由 `code → notepad` 改为 **`trae → code → notepad`**；config editor / $EDITOR 仍最高优先 |
| 备选否决 | 命令层各自分流（9 处改动、行为易不一致）；行命令式编辑（体验繁琐）；注册表读默认应用（复杂脆弱） |

## 3. 总体流程

```
按 e / /logs edit → editOpen → edit.Open(path)
                                 ├─ 读文件，行数 ≤ 20 → CLI 全屏编辑器
                                 └─ 行数 > 20 → 外部编辑器（splitEditor 解析）
编辑器退出 → pager 自动重渲染（现有行为不变）
```

空文件（新建当日日志）按 0 行算，走 CLI。

## 4. CLI 全屏编辑器交互规格（新增 `internal/edit/inline.go`）

| 按键 | 行为 |
|---|---|
| ↑↓←→ / Home / End | textarea 标准光标移动与增删改 |
| Ctrl+S | 保存并退出（`workspace.WriteFileAtomic` 原子写） |
| Esc | 退出；若有未保存修改，先确认「放弃修改？(y/N)」 |

- 顶部一行标题：`编辑 Study/logs/261026.md · Ctrl+S 保存退出 · Esc 退出`，沿用 ui 主题色系，无 emoji（硬性规则）
- 换行风格保留：原文件含 CRLF 则写回 CRLF，否则 LF（textarea 内部一律 \n）

## 5. 边界与降级

- tea 程序启动失败（极老终端等）→ 自动降级走外部编辑器，不报错中断
- `shouldCliEdit`、换行风格保留、保存逻辑拆为纯函数，可独立测试
