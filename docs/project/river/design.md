# river · 河流层设计

日期：2026-10-27
状态：**AI 起草，待开发者审核定稿**——依开发者指示从「三层学习框架」正本（现 `docs/project/全局/三层学习框架-design.md`）按层拆分补充；决策全部来自该正本已定案条目，并对照代码现状（`internal/command/tier_cmd.go` 等）核实，未新增需求。

## 1. 定位

河流是三层学习框架的第二层：**摘录沉淀**。从大海中筛选出的、有价值需要反复学习的内容；仍不是原创手写，只是学习的沉淀，不完全属于自己。sea 回答「外部知识存在哪」，river 回答「哪些值得反复看」。

## 2. 存储结构

`Study/river/`，一主题一文件。条目头部自动带出处行：

```
# <主题>

> 出处：Study/sea/<来源条目>.md
```

出处链默认自动带（Q4 定案），供 /review 反查「大海未摘录」与跨层溯源。

## 3. 命令行为（Q4/Q5 定案 + 实现核对）

| 命令 | 行为 |
|---|---|
| `/river [关键词]` | 查阅：按 roadmap 主干分组两级选择，未绑定文件归尾部「未挂载」组；有关键词平铺直选，唯一命中直达 |
| `/river add [关键词]` | 摘录：选 sea 条目 → 起主题名（回车默认源条目名）→ 创建预填「出处 + 全文」的 river 条目 → 调起编辑器（全文摘录=直接保存退出；选段摘录=编辑器内删减后保存）→ 尾部追问「挂到知识点？」（关键词过滤定位，回车跳过） |
| `/river edit [关键词]` | 选择条目调起编辑器 |

实现期决策：Q4 原设想的「确认摘录范围（全文/选段）」合并为编辑器一步——全文直存或编辑器内删减存。

## 4. 与 roadmap 的绑定

知识点（`Study/plan/roadmap.toml` 的 Point）通过 `river` 字段**多绑** river 条目（追加、幂等）；`/river add` 尾部追问与 `/plan` 浏览器共用绑定。层查看与绑定以磁盘为准：绑定指向不存在文件的「幽灵绑定」不展示，未绑定文件归「未挂载」组。路线图不存在时挂载追问静默跳过。

## 5. 与其他模块的关系

- **sea**：摘录源头（出处链指向）。
- **spring**：改写流向（river 是「待改写清单」的来源，/review 据此提示）。
- **show**：「知识」节 river 条目优先展示。
- **review**：三层统计中「河流待改写清单」的数据源。
