# show · 验收演示模块设计

日期：2026-10-27
状态：**AI 起草，待开发者审核定稿**——依开发者指示补充模块正本；需求源自 `全局/design.md` §5.2/§7.1 与三层框架正本中的「/show 模块在新框架下的安排」章节，并对照代码现状（`internal/command/show.go`、`internal/index`）核实整理。

## 1. 定位

/show 是跨层聚合的验收演示**视图**，不是存储层——不产生新的内容存放地，素材全部实时引用现有位置；topics.toml 沉淀索引只存「引用 + 演示提示」。三层回答「知识存在哪、怎么流」，/show 回答「知识怎么讲给人听」。

## 2. 入口

| 形式 | 行为 |
|---|---|
| `/show` | 进入主题选择：已沉淀主题 + 热门关键词（提取源：日志 + 三层标题，去停用词） |
| `/show <主题>` | 直达该主题的五节演示视图 |

## 3. 五节视图（新框架形态）

| 节 | 内容 |
|---|---|
| ① 概览 | 主题统计行（知识/代码/日志/面试题命中数）与操作提示 |
| ② 知识 | river/spring 条目优先展示（正文节选），sea 作补充（大海杂多，不作演示主体） |
| ③ 代码 | 命中的 .go 文件列表（含命中次数），演示时用 o 打开文件结合行号讲解 |
| ④ 日志 | 命中的日志行（按文件） |
| ⑤ 面试题 | 路径或内容含 interview/面试 的 md；`sea/interview/` 正本为主，项目内残留一并纳入（面试题优先于知识节归类） |

某节无内容时显示「（无相关内容）」。

## 4. 双来源：索引优先，实时扫描兜底

- `.gs/topics.toml` 已有该主题 → 按索引引用构建视图（files 引用 + hint 演示提示，hint 以〔提示〕形式附在条目后）。
- 无索引 → 实时扫描（/search 引擎，多词 AND）生成。
- 索引条目展示前校验文件存在性，失效条目标灰并提示清理（依赖现有机制，不写专门迁移逻辑）。

## 5. 操作键

| 键 | 行为 |
|---|---|
| `n` / `p` | 下一节 / 上一节 |
| `o` | 打开当前节的文件（菜单选择 → 调起编辑器） |
| `s` | 把当前实时扫描视图沉淀为索引条目（已在索引则提示 /show edit 维护） |
| `q` / Esc | 退出 |

## 6. 沉淀索引与维护

- 沉淀写入 `<root>/.gs/topics.toml`（原子写）；`files` 引用工作区相对路径（正斜杠），每条可写一句 hint 演示提示（如「重点讲 3 个 goroutine 泄漏的例子」）。
- `/show edit` 维护已有主题的索引（改 hint、清理失效条目）。
- 旧索引中失效路径随标灰提示机制自然清理，不写专门迁移逻辑。

## 7. 代码结构

| 包 | 职责 |
|---|---|
| `command/show.go` | 五节视图构建（索引/扫描双来源）、pager 交互、沉淀 |
| `internal/index` | topics.toml 读写（原子写、按名查找） |
| `internal/search/hot.go` | 热门关键词提取（日志 + 三层标题） |
