## AI 模式 tools 400 报错修复

> 创建于 2026-10-27 00:39

- 现象：/AI 首问即报 HTTP 400 `tools[0].type: type cannot be empty`；此前无工具时 tools 被 omitempty 整体省略，Agent 化首次带 tools 才暴露
- 根因：ai.Tool 序列化为裸 {name,description,parameters}，缺 OpenAI 规范外层 {"type":"function","function":{...}}
- 修复：Tool 加自定义 MarshalJSON（plain 逐字复制避免递归），内部扁平定义与构造方全部不动
- 测试：新增 TestChatWithToolsWireFormat 断言外壳格式，先 RED（复现线上 400 同因）后 GREEN；go build + go test ./... 全绿
- 二轮实测仍 400（错误移位至「工具类型不能为空」）：首轮 tools 已被接受、模型正常发起工具调用，但第二轮回传 assistant.tool_calls 同为裸格式
- 续修：ToolCall 加 MarshalJSON，输出 {"id","type":"function","function":{name,arguments}}（id 在外层）；RED 阶段即抓到 id 误嵌 function 的规范偏差并纠正
- 教训：agent_test 假客户端不走真实 JSON 序列化，wire 格式必须在 ai 层断言；新增 TestChatWithToolsToolCallWireFormat，go test ./... 退出码 0
