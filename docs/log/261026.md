## 修复：自绘输入行退出后命令无输出

> 创建于 2026-10-26 09:40

**现象**：开发者冒烟发现输入 `/logs` 回车后无任何显示，所有命令均无响应输出。

**根因**（读 bubbletea v1.3.6 源码定位）：`standardRenderer.stop()` 退出时执行 `EraseEntireLine` + `\r`，把光标所在的已输入命令行擦掉；且程序退出后 Windows 控制台的输入/输出模式残留不还原，后续命令输出落在行中、模式错位，表现为全部命令「无显示」。

**修复**（`repl/line.go` 的 `Read`）：tea 程序运行前 `term.GetState` 存 stdin/stdout 控制台状态，退出后 `term.Restore` 还原；提交非空行后主动回显 `prompt+result`（补回被擦掉的行）并补一个换行，保证后续输出另起一行。

**验证**：`go build` + `go vet` + repl/complete 测试全绿；真实终端待开发者复测（重编译后 `/logs`、`/help`、候选面板、↑↓ 历史逐项试）。

## 修复（真因）：VS Code/trae 终端 Enter 以 \n 送达导致命令永不提交

> 创建于 2026-10-26 15:05

**取证**：控制台模式还原后仍复现。逐层取证——终端为 trae/VSCode 内置终端；**打字可见（输入驱动正常）、回车无反应（提交路径未触发）**；plain 通道未试。据此锁定按键映射层。

**根因**：xterm.js 系终端的 Enter 可能以 `\n` 送达，bubbletea 将其映射为 `KeyCtrlJ` 而非 `KeyEnter`；teaReader 的提交分支只认 `KeyEnter`，导致永远不提交——输入停在行内，所有命令「无响应」。

**修复**（TDD，新增 `repl/line_test.go`）：先写 `TestLineModelSubmitKeys` 证明 KeyCtrlJ 不提交（RED），提交分支改为 `case tea.KeyEnter, tea.KeyCtrlJ` 后转绿（KeyCtrlM 与 KeyEnter 为同一常量，无需单列）。

**验证**：`go build` + `go vet` + 全量 11 包全绿；待开发者在 trae 终端重编译复测（/logs 输出、面板、历史、ai>）。

**关联提醒**：huh 选择器（/sea import 起标题、长日志确认等）同为 bubbletea 程序，在同终端可能存在同类 Enter 差异——此前交互路径未实测过，若遇「选项回车无反应」属同一现象，届时统一处理。

**涉及文件**：`internal/repl/line.go`、`internal/repl/line_test.go`（新）

## 修复（终因）：Enter 残留 \n 污染输入缓冲，分页器瞬退

> 创建于 2026-10-26 15:40

**取证**（GS_KEYLOG 按键日志，开发者实测）：`/logs` 两次回车的记录为 `enter ×2` + 杂散 `\x00`——**Enter 以标准 KeyEnter 正常送达**，前一轮的键映射假设被证伪。两次回车都被 tea 程序收到 = 查阅分页器瞬间退出、从未接住按键。

**根因**：ConPTY 对 Enter 交付 `\r\n`；bubbletea 消费 `\r`（→KeyEnter→提交→Quit）后，`\n` 残留在控制台输入缓冲。下一位读者（`runViewPager` 的 bufio/分页器）一启动就读到残留换行 → 等价于按「q」→ 瞬间退出回输入行。循环往复，表现为「命令闪没、全无输出」。此前两轮修复（模式还原、KeyCtrlJ）均未触及此层。

**修复**：新增 `repl/drain_windows.go`（`FlushConsoleInputBuffer` 清控制台输入缓冲，`drain_other.go` 非 Windows 空实现），`teaReader.Read` 在起程序前后各冲一次——启动前清上轮残留，退出后清本轮 Enter 的 `\n`。

**验证**：`go build` + `go vet` + 全量 11 包全绿；待开发者重编译后在 trae 终端复测（/logs 应稳定进入查阅循环；GS_KEYLOG 复跑一次确认 enter 后无杂散事件）。

**涉及文件**：`internal/repl/drain_windows.go`（新）、`internal/repl/drain_other.go`（新）、`internal/repl/line.go`、`go.mod`、`go.sum`

## 修复 AI 模式超宽输入每键重打全文的叠影 bug

> 创建于 2026-10-26 23:16

**反馈**：AI 模式输入到一定字数后，再按任何键都会重复显示一遍「提示符+全文」，越叠越多。

**根因**：`rawreader.go` 的 `draw()` 把输入行当单行渲染——`\x1b[J` 只清光标所在行及以下、`\x1b[NC` 定位不换行；当「提示符+文本+ghost」显示宽度（中文每字 2 列）超过终端列宽时终端自动换行，旧内容清不掉、光标定位错位，每键重打全文形成叠影。

**实现**（TDD，先红后绿）：linerender.go 新增 `inputWindow`（按显示宽度选含光标的可见窗口，宽字符跨界整字移出防切半）、`truncateByWidth`（ghost 按剩余列截断）、`buildInputLineFit`（窗口化渲染，返回光标列）；`draw()` 改用「终端列数 − 提示符宽 − 1」的 avail 裁剪，新增 `terminalWidth()`（`term.GetSize`，失败退 80）。删除无调用方的 `cursorColumn`。

**验证**：`go build ./...` + `go test ./...` 15 包全绿；新增 8 个窗口/截断/渲染测试。真机冒烟待开发者：AI 模式连打长中文（约 40 字以上）不应再出现叠影，行满后应左滚、光标始终可见。

**涉及文件**：`internal/repl/linerender.go`、`internal/repl/rawreader.go`、`internal/repl/linerender_test.go`
